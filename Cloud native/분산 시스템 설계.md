# 분산 시스템 설계 (Distributed Systems Design)

**분산 시스템 설계(Distributed Systems Design)**는 여러 독립적인 컴퓨터들이 네트워크를 통해 협력하여 **단일 시스템처럼 동작**하도록 만드는 설계 방식입니다. 분산 시스템은 하나의 시스템에 장애가 발생해도 다른 시스템이 이를 보완할 수 있는 **가용성**, **확장성**, **복원력**이 중요한 목표입니다. 이 설계는 클라우드 컴퓨팅, 마이크로서비스, 대규모 애플리케이션 등에서 필수적인 개념입니다.

## 분산 시스템의 주요 목표

1. **확장성 (Scalability)**: 시스템이 수평적으로 확장될 수 있는 능력. 더 많은 트래픽이나 데이터를 처리하기 위해 추가적인 노드를 쉽게 추가할 수 있어야 합니다.
2. **가용성 (Availability)**: 시스템이 항상 사용 가능하며, 일부 노드가 실패하더라도 전체 시스템이 계속 동작할 수 있어야 합니다.
3. **일관성 (Consistency)**: 모든 노드에서 데이터를 읽고 쓸 때 동일한 상태를 보장하는 능력. 여러 복제본 간의 데이터 일관성을 유지하는 것이 중요합니다.
4. **복원성 (Fault Tolerance)**: 시스템이 일부 장애에도 불구하고, 전체적인 기능을 유지하고 자동으로 복구할 수 있는 능력.

## 분산 시스템 설계의 핵심 개념

### 1. **CAP 이론 (CAP Theorem)**

CAP 이론은 분산 시스템에서 **일관성(Consistency)**, **가용성(Availability)**, **네트워크 분할 허용성(Partition Tolerance)** 중 **동시에 두 가지 특성**만을 보장할 수 있다는 이론입니다.

- **Consistency (일관성)**: 모든 노드가 동일한 데이터를 가지고 있음.
- **Availability (가용성)**: 모든 요청이 성공적으로 응답을 받음.
- **Partition Tolerance (네트워크 분할 허용성)**: 네트워크 장애에도 시스템이 계속 동작할 수 있음.

분산 시스템에서는 일반적으로 **가용성**과 **네트워크 분할 허용성**을 우선하며, 일관성을 **최종 일관성(Eventual Consistency)**으로 타협하는 경우가 많습니다.

### 2. **일관성 모델 (Consistency Models)**

분산 시스템에서 일관성을 유지하는 방식은 다양한 모델로 나뉩니다.

- **강한 일관성 (Strong Consistency)**: 모든 노드가 항상 같은 데이터를 가지고 있어야 합니다. 즉, 쓰기가 완료되면 모든 읽기 요청은 최신 데이터를 반환합니다.
- **약한 일관성 (Weak Consistency)**: 쓰기가 완료되더라도, 모든 노드가 즉시 최신 상태를 반영하지 않으며, 일시적으로 다른 데이터를 반환할 수 있습니다.
- **최종 일관성 (Eventual Consistency)**: 시간이 지나면 결국 모든 노드가 일관된 상태에 도달하게 됩니다. 분산 시스템에서 자주 사용하는 모델로, 네트워크 분할 시 가용성을 우선할 때 유용합니다.

### 3. **리더 선출 (Leader Election)**

분산 시스템에서 여러 노드가 협력할 때, 특정한 노드가 **리더 역할**을 해야 할 경우가 있습니다. 리더는 다른 노드의 요청을 관리하거나 조율하는 역할을 하며, 장애가 발생하면 새로운 리더를 선출해야 합니다.

- **알고리즘**: Paxos, Raft 같은 분산 합의 알고리즘을 사용하여 리더를 선출합니다.

### 4. **분산 트랜잭션 (Distributed Transactions)**

분산 시스템에서 데이터 일관성을 보장하기 위한 **트랜잭션 관리**가 필요합니다. 트랜잭션은 **ACID**(Atomicity, Consistency, Isolation, Durability) 원칙을 따라야 하지만, 분산 시스템에서는 이를 보장하는 것이 매우 어렵습니다.

- **2PC (Two-Phase Commit)**: 분산 시스템에서 트랜잭션을 일관성 있게 커밋하기 위한 프로토콜로, 두 단계로 나누어 트랜잭션을 수행합니다.

  1. **준비 단계(Prepare Phase)**: 모든 노드에게 커밋 준비가 되었는지 확인.
  2. **커밋 단계(Commit Phase)**: 모든 노드가 준비 완료를 알리면 트랜잭션을 커밋.

- **SAGA 패턴**: 장기 실행 트랜잭션을 여러 로컬 트랜잭션으로 분할하고, 각각이 성공하면 다음 트랜잭션을 진행하는 방식입니다. 트랜잭션 실패 시, 이전에 실행된 트랜잭션을 **보상 작업**으로 롤백하는 방식을 사용합니다.

### 5. **샤딩 (Sharding)**

**샤딩**은 데이터베이스나 저장소를 여러 개의 작은 조각으로 나누어 **수평적으로 분산**시키는 방법입니다. 이를 통해 대규모 데이터를 효율적으로 저장하고 처리할 수 있습니다.

- **예**: 사용자 ID에 따라 데이터를 여러 서버에 분산 저장함으로써 각 서버의 부하를 줄이고 성능을 향상시킵니다.

### 6. **복제 (Replication)**

**복제**는 데이터를 여러 노드에 **복사**하여 **고가용성**과 **데이터 안정성**을 확보하는 방법입니다. 복제된 데이터는 장애가 발생해도 다른 복제본을 통해 데이터를 복구할 수 있습니다.

- **종류**:
  - **마스터-슬레이브 복제**: 마스터 노드에서 쓰기 작업이 이루어지고, 슬레이브 노드가 읽기 작업을 담당.
  - **다중 마스터 복제**: 여러 마스터 노드가 동시에 쓰기 작업을 처리할 수 있음.

### 7. **이벤트 소싱 (Event Sourcing)**

이벤트 소싱은 **상태 변경을 이벤트로 기록**하고, 이벤트의 흐름을 기반으로 시스템의 상태를 복원하는 방식입니다. 이를 통해 모든 변경 사항을 추적할 수 있으며, 시스템 복구나 리플레이(replay)가 용이합니다.

- **예**: 은행 거래 시스템에서 모든 트랜잭션을 이벤트로 기록하여 계좌의 최종 상태를 언제든지 재구성할 수 있음.

### 8. **CQRS (Command Query Responsibility Segregation)**

**CQRS**는 **명령(Command)**과 **조회(Query)** 작업을 분리하여, 서로 다른 데이터 모델을 사용하는 설계 패턴입니다. 이를 통해 쓰기와 읽기 작업을 최적화할 수 있습니다.

- **명령**: 데이터를 변경하는 작업.
- **조회**: 데이터를 읽는 작업.

CQRS는 특히 **대규모 시스템**에서 **읽기 작업과 쓰기 작업을 분리**하여 성능을 최적화하는 데 유용합니다.

## 분산 시스템의 도전 과제

### 1. **네트워크 장애**

분산 시스템에서는 네트워크 장애가 빈번하게 발생할 수 있습니다. 네트워크 지연, 패킷 손실, 연결 끊김 등의 문제가 생길 때 **서비스 중단** 없이 시스템이 동작해야 합니다.

### 2. **데이터 일관성**

분산된 노드 간의 데이터 일관성을 유지하는 것은 매우 어렵습니다. 노드 간에 데이터 복제본이 여러 개 존재할 수 있기 때문에, 일관성을 유지하면서도 가용성과 성능을 극대화하는 것은 분산 시스템 설계의 중요한 과제입니다.

### 3. **합의 알고리즘**

분산 시스템에서 노드 간 합의를 이끌어내기 위한 알고리즘은 매우 중요합니다. 합의 알고리즘은 노드가 서로 동의하는 결정을 내리는 데 사용됩니다.

- **대표 알고리즘**: Paxos, Raft

### 4. **분산 트레이싱**

분산 시스템에서 요청이 여러 서비스에 걸쳐 처리될 때, 각 서비스 간의 **트랜잭션 흐름을 추적**하는 것은 매우 어렵습니다. 이를 해결하기 위해 **분산 트레이싱** 기술이 사용되며, 이는 서비스 간 요청 흐름을 시각화하고, 병목 구간을 파악하는 데 유용합니다.

## 대표적인 분산 시스템 기술

1. **Apache Kafka**: 분산형 메시징 시스템으로, 대용량 데이터 스트리밍 및 실시간 데이터 처리를 위한 기술.
2. **Kubernetes**: 컨테이너화된 애플리케이션을 관리하는 오케스트레이션 플랫폼.
3. **Apache Zookeeper**: 분산 애플리케이션을 위한 코디네이션 서비스로, 분산 락, 리더 선출, 구성 관리 등을 제공.
4. **Cassandra**: 높은 확장성과 가용성을 제공하는 분산형 NoSQL 데이터베이스.

---

분산 시스템 설계는 대규모 애플리케이션을 확장 가능하고, 안정적이며, 복구 가능한 상태로 운영하는 데 필수적인 기술입니다. **CAP 이론**, **일관성 모델**, **복제**, **샤딩** 등의 개념을 이해하고 적절히 적용함으로써 **확장성**, **가용성**, **일관성**을 유지하는 것이 중요합니다.
