# 관찰 가능성 (Observability)

**관찰 가능성(Observability)**은 클라우드 네이티브 환경에서 애플리케이션의 **상태**와 **행동**을 모니터링하고, 문제를 사전에 감지하고 해결할 수 있는 능력을 의미합니다. 단순한 모니터링을 넘어 시스템 내부에서 어떤 일이 일어나고 있는지 **실시간으로 파악**하여, 성능 문제나 장애를 신속하게 해결할 수 있도록 도와줍니다.

관찰 가능성은 주로 **로그**, **메트릭**, **트레이싱**과 같은 세 가지 주요 요소를 통해 이루어지며, 이를 통해 복잡한 마이크로서비스 환경에서 **투명성**을 확보하고 **문제 해결**을 용이하게 합니다.

## 1. 로그 (Logs)

**로그**는 애플리케이션에서 발생한 이벤트에 대한 **기록**입니다. 로그는 주로 디버깅이나 특정 시점에서 발생한 **오류**를 추적할 때 사용됩니다.

- **특징**:
  - 애플리케이션이나 서비스에서 발생한 중요한 이벤트 기록.
  - 에러, 경고, 정보 메시지를 통해 문제 원인을 파악.
  - 로그 데이터는 **중앙 집중화**되어 관리되며, 이를 통해 다양한 시스템의 로그를 한 곳에서 조회 가능.
- **도구**: ELK Stack (Elasticsearch, Logstash, Kibana), Fluentd, Loki

## 2. 메트릭 (Metrics)

**메트릭**은 애플리케이션의 **상태나 성능**에 대한 **숫자 데이터**로, 주기적으로 수집됩니다. 메트릭을 통해 애플리케이션의 **성능**, **자원 사용량**, **응답 시간** 등을 모니터링할 수 있습니다.

- **특징**:
  - CPU, 메모리 사용량, 네트워크 트래픽, 요청 수, 에러율 등의 정량적 데이터 제공.
  - 실시간 모니터링과 경고 알림을 설정하여 문제가 발생하기 전에 대응 가능.
  - 시계열 데이터로 분석 가능.
- **도구**: Prometheus, Grafana, Datadog, New Relic

## 3. 분산 트레이싱 (Distributed Tracing)

**분산 트레이싱**은 마이크로서비스 환경에서 **요청이 여러 서비스에 걸쳐** 처리되는 과정을 **추적**하는 기술입니다. 이를 통해 특정 요청이 어떤 서비스에서 얼마만큼의 시간이 소요되었는지, 그리고 어디에서 병목이 발생했는지를 파악할 수 있습니다.

- **특징**:
  - 복잡한 서비스 간 요청 흐름을 시각화.
  - 병목 구간, 지연 시간, 실패한 서비스 등을 추적.
  - 요청 경로 상에서 어느 지점에서 문제가 발생했는지 파악 가능.
- **도구**: Jaeger, Zipkin, OpenTelemetry

## 4. 관찰 가능성의 중요성

### 1. **빠른 문제 해결**

관찰 가능성은 시스템에서 문제가 발생했을 때 **즉시 원인**을 파악하고 **신속하게 대응**할 수 있게 해줍니다. 특히 마이크로서비스 환경에서는 서비스 간의 복잡한 상호작용 때문에 문제를 추적하기 어려운데, 로그, 메트릭, 트레이싱을 활용하면 문제의 **근본 원인**을 빠르게 찾을 수 있습니다.

### 2. **능동적인 모니터링**

관찰 가능성은 단순히 문제가 발생한 후에 추적하는 것이 아니라, **능동적으로 시스템의 상태를 모니터링**하고, 잠재적인 문제를 **사전에 감지**하여 대응할 수 있도록 도와줍니다.

### 3. **비즈니스 성능 향상**

애플리케이션의 성능 데이터를 수집하고 분석하여 **최적화**할 수 있습니다. 예를 들어, 트래픽 증가에 따라 서버 자원을 자동으로 확장하거나, 성능 병목 구간을 최적화하여 더 나은 사용자 경험을 제공할 수 있습니다.

### 4. **신뢰성과 가용성 향상**

관찰 가능성을 높임으로써 애플리케이션의 **신뢰성**과 **가용성**을 극대화할 수 있습니다. 성능 문제를 사전에 해결하거나, 장애 발생 시 빠르게 대응할 수 있어 **서비스 중단 시간**을 최소화할 수 있습니다.

## 5. 대표적인 도구

### 1. **Prometheus & Grafana**

- **Prometheus**는 메트릭 수집과 경고를 담당하며, **Grafana**는 이를 시각화하여 실시간 대시보드를 제공합니다.
- **활용 예시**: CPU 사용률, 메모리 소비, 네트워크 트래픽과 같은 시스템 메트릭을 실시간으로 모니터링하고, 특정 임계값을 넘으면 경고를 발송.

### 2. **ELK Stack**

- **Elasticsearch, Logstash, Kibana**를 결합한 도구로, 로그 데이터를 수집, 검색, 시각화할 수 있습니다.
- **활용 예시**: 애플리케이션 에러 발생 시 로그 데이터를 수집하고, Kibana를 통해 특정 시간대의 로그를 분석하여 원인을 파악.

### 3. **Jaeger**

- 분산 트레이싱 도구로, 마이크로서비스 간의 요청 흐름을 추적하고 시각화합니다.
- **활용 예시**: 특정 요청이 어느 서비스에서 지연되었는지 추적하여 성능 병목을 해결.

### 4. **Zipkin**

- Jaeger와 유사한 분산 트레이싱 도구로, 요청 경로를 추적하고 병목 구간을 시각화하여 문제 해결에 도움을 줍니다.

## 관찰 가능성과 모니터링의 차이

관찰 가능성은 **단순 모니터링을 넘어선 개념**입니다. 전통적인 모니터링은 미리 정의된 지표(CPU 사용량, 메모리 사용량 등)를 중심으로 시스템을 관찰하는 반면, 관찰 가능성은 시스템 내부의 상태를 더 **깊이 이해**하고 **복잡한 문제를 추적**할 수 있도록 지원합니다.

---

관찰 가능성은 마이크로서비스와 같은 **복잡한 클라우드 네이티브 아키텍처**에서 필수적인 요소입니다. 로그, 메트릭, 트레이싱을 통합적으로 활용하여 시스템의 상태를 실시간으로 파악하고, 문제를 신속하게 해결하며, 성능을 최적화할 수 있습니다. 이를 통해 **서비스의 안정성**과 **가용성**을 높이고, 더 나은 사용자 경험을 제공합니다.
